# Glass: нативная проба управляемого размытия

Дата: 2026-10-28. Это технический результат отдельной программы, ещё не
реализация эффекта в Таймере.

## Подключение к dev-Таймеру

Следующая проба уже подключает механизм к основному окну Tauri/WebView2.
Общий нативный модуль `bsl-desktop-window` 0.7.0 содержит C++/WinRT backend,
статически собираемый MSVC через `cc` 1.2.64. Он включается только feature
`composition-preview`; потребитель выбирает `native-glass-preview`.
Без feature остаётся прежний нативный путь оформления.

Код живёт в `bsl-core/native/window`, Таймер обеспечивает передачу операции
на UI-поток. Очередь WinRT и COM-объекты остаются на этом потоке. Слой
помещается под WebView2, его размер отслеживает WM_SIZE/WM_DPICHANGED.
Он не создаёт второго окна, не получает фокус и не перехватывает мышь.
При выходе из Glass слой удаляется; изменённый флаг перенаправления окна
восстанавливается. При ошибке создания выполняется очистка без серой заливки.

Проба запущена штатным Tauri dev с внешним Vite-сервером, без передачи кода
в аргументах Node и без изменения исключений Defender. Начальное значение
Gaussian Blur — 0,75 с учётом DPI. Временно задаётся переменной запуска
`BSL_GLASS_BLUR_SIGMA` в пределах 0..8; пользовательского ползунка пока нет.

Выполнено:

- `cargo build --features native-glass-preview --offline`: успешно.
- `cargo check --offline` без экспериментального feature: успешно.
- `npm test`: 106 тестов прошли.
- Dev-приложение запущено после подтверждённого пользователем закрытия
  предыдущего EXE. В журнале: `Glass native composition active: sigma=0.75`.
- Просмотрен снимок `native-webview-glass.png`: WebView2 отображается,
  фон виден через материал, цифры чёткие, чёрной поверхности нет.
- На последовательных снимках отсчёт продолжается; через Windows UI Automation
  доступны кнопки и настройки.

Автоматическая проверка переключения Light/Dark не подтверждена: UIA-провайдер
списка не дал проверенного изменения значения, клавиши при неподтверждённом
фокусе не отправлялись. Соответствующие ранние снимки с названиями light/dark
не являются доказательством этих режимов. Пользователю предложена ручная
проверка Light → Dark → Glass. Полная нативная матрица и замеры CPU/GPU
ещё не выполнены. Выпуска и нового установщика нет; прежние пользовательские
таймеры в установленной версии не удалялись.

Исходная точка и конфигурация запуска:
`.task-backups/glass-native-integration-2026-10-28`.

## Проверенная проба

Исходники и результаты находятся в
`.task-backups/glass-native-research-2026-10-28`:

- `probe.cpp`: отдельное Win32-окно и Windows.UI.Composition.
- `build-probe.cmd`: сборка установленным MSVC и Windows SDK без загрузки
  библиотек и без изменения проекта Таймера.
- `glass-native-probe.exe check`: скрытая проверка создания API-объектов.
- `run-probe.ps1`: запуск окна на 12 секунд и контрольный снимок.
- `probe-backdrop.png`, `result-backdrop.txt`: визуальный результат и журнал.

На Windows 10 Pro, build 19045.6466, успешно созданы Compositor,
DesktopWindowTarget, стандартный BackdropBrush и GaussianBlur effect.
Окно поделено на две половины: параметр Gaussian Blur слева 0, справа 2.
На снимке виден реальный текст другого окна под пробой: слева он чёткий,
справа размыт. Это не изображение, помещённое внутрь пробного окна.
Проба не использует Desktop Duplication, Windows.Graphics.Capture или
чтение пикселей рабочего стола для отрисовки. Снимок для контроля сделан
отдельно, после вывода эффекта. Окно завершилось штатно по таймеру.

Параметр 2 относится к Gaussian Blur, а не к измеренной толщине стекла
или диаметру оптической линзы. Отдельный эффект преломления не реализован.

## Существенное ограничение

Для доступа к содержимому за окном проба использует
`SetWindowCompositionAttribute` с `ACCENT_ENABLE_HOSTBACKDROP` (5).
Этот путь не следует считать документированным универсальным контрактом
Windows. Подтверждена только работа указанной связки на текущей машине.
Документированный Win32-флаг `DWMWA_USE_HOSTBACKDROPBRUSH` поддерживается
начиная с Windows 11 build 22000, поэтому не является прямой заменой для
нынешней Windows 10.

## Что ещё требуется проверить

1. Совместимость нативного графического слоя с дочерним WebView2 Таймера.
   Нативная проба не доказывает, что слой можно без конфликтов разместить
   под существующим WebView2 в том же окне.
2. Низкие значения размытия, форма и отсечение по контуру корпуса.
3. Перемещение, скрытие/показ, переключение Glass и обычных оформлений,
   DPI и мониторы, отсутствие потери фокуса и перехвата мыши.
4. Реальная нагрузка CPU/GPU. Замеров производительности пока нет.
5. Поведение при недоступности эффекта и поддержка других версий Windows.

До этих проверок нативный эффект не подключён к продукту, в настройках
нет нового ползунка. Данные и настройки таймеров пробой не менялись.

## Первичные источники

### Проверка захвата экрана, 2026-10-28

#### Уточнение и следующая нативная проба

PrtScn назначен на RectangleRegion в ShareX 21.0.0. Запуск той же операции
через CLI без клавиши также воспроизводит черноту. Одиночный GDI-захват области
Таймера с CAPTUREBLT и совместимым bitmap сохраняет фон. Захват всего виртуального
рабочего стола тем же кодом чернит размытие на дополнительном мониторе с
отрицательной координатой X. Отдельная Win32-проба воспроизводит различие между
основным и дополнительным мониторами, без Tauri/WebView2.

Смена оптимизации Gaussian Blur, мягкая граница эффекта и непрозрачность 0,999
не решили проблему. В отдельной пробе помогла промежуточная CompositionVisualSurface:
исходный BackdropBrush помещён в отдельный SpriteVisual, его поверхность с явным
SourceSize подаётся в эффект через CompositionSurfaceBrush. Нет чтения пикселей
рабочего стола или распознавания снимков. Контрольный файл:
`.task-backups/glass-capture-opacity-2026-10-28/local-surface-full.png`.

Этот вариант перенесён в общий экспериментальный backend и собран отдельным
EXE `src-tauri/target/glass-capture-preview/bsl-timer.exe` через cargo rustc с
другим именем выходного файла.

Итог живой проверки: после выхода пользователя из предыдущего экземпляра
запущен этот EXE. PrtScn/ShareX больше не чернит материал; проверены повторный
вызов на другом фоне и полный GDI-захват виртуального рабочего стола. Пользователь
подтвердил результат собственным снимком. Проверка относится к текущей Windows 10
и дополнительному монитору с отрицательными координатами, не к полной матрице
версий Windows/драйверов. Снимки сохранены в
`.task-backups/glass-edge-fix-2026-10-28/`.

В живой dev-пробе с активным отсчётом воспроизведён чёрный фон при PrtScn.
В системе работает ShareX; после выхода из выбора области стеклянный фон
возвращается. При Win + Shift + S фон сохраняется в изображении выбора области
(со штатным затемнением инструмента Windows). Обычный диагностический захват
через CopyFromScreen также сохраняет фон. Отсчёт во время проверок продолжался.

Принудительный WCA_FORCE_ACTIVEWINDOW_APPEARANCE и временное снятие
WS_EX_NOREDIRECTIONBITMAP не устранили черноту при PrtScn. После проверки
экспериментальные изменения этих атрибутов восстановлены. Производственный код,
тема, палитра и сила размытия этой диагностикой не менялись.

На этапе первичной диагностики это был дефект совместимости материала с захватом,
а не подтверждённое переключение оформления. Win + Shift + S — проверенный
временный путь для визуального обсуждения; исправлением PrtScn он не считается.
Диагностические файлы: `.task-backups/glass-capture-fix-2026-10-28/`.
